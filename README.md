# 1C · Платёжные ордера (тестовый интерфейс пользователя)

Bootstrap-интерфейс «как для обычного пользователя» поверх стандартного OData 1С
(Unisoft, 1С:Бухгалтерия). Цель — руками пройти весь сценарий интеграции
(справочники → создание платёжного ордера → проведение) и увидеть ошибки 1С.

```bash
cp .env.example .env   # заполнить ODATA_PASSWORD
npm start              # http://localhost:3200
```

`server.js` — zero-dependency Node: отдаёт `public/`, проксирует `/odata/*` в 1С с
Basic-auth из `.env`.

## Что есть
- Списки с поиском/пагинацией: Организации, Контрагенты, Банковские счета, План счетов,
  Платёжные ордера (поступление ДС). Клик по строке — карточка, все `*_Key` показаны именами.
- Форма «Создать ордер»: организация → её р/с, контрагент (поиск по названию/ИНН) → его счёт,
  вид операции, счёт учёта (Дт), счёт расчётов с контрагентом (Кт), расшифровка платежа.
  Показывает JSON, который уйдёт в 1С.
- Действия над документом: Провести / Отменить проведение / Пометить на удаление.
- Ошибки 1С показываются текстом 1С + список известных причин.

## Что выяснилось на тестовой базе
- `ВидОперации = ПрочееПоступлениеБезналичныхДенежныхСредств` **не проводится** без
  `СчетУчетаРасчетовСКонтрагентом_Key` (Кт проводки). С ним проводится (проверено:
  UG000000285 — Кт 4610, UG000000286 — Кт 6990).
- Сообщение 1С при отказе в проведении общее («Не удалось провести …»), причина через
  OData не приходит — смотреть в 1С или подбирать по подсказкам в интерфейсе.
- `Catalog_СтатьиДвиженияДенежныхСредств` и договоры контрагентов в OData не опубликованы —
  статья ДДС вводится GUID'ом (в форме есть список используемых в базе).

## Как отдать коллеге
Нужен только Node.js (18+). Скопировать папку **без `.env`** (он в `.gitignore`), затем:

```bash
node server.js          # или node server.js 4000 — другой порт
```

При первом открытии http://localhost:3200 появится окно «Подключение»: URL OData, логин и
пароль 1С. Кнопка «Проверить» делает пробный запрос к service root, «Сохранить» — запоминает
в localStorage этого браузера (сервер ничего не хранит). Сменить/забыть — кнопка
«Подключение» в шапке. Если в папке есть `.env` — он работает как значения по умолчанию,
и в окне появляется кнопка «Использовать серверные».

## Netlify
Проект готов к деплою на Netlify без сборки: статика из `public/`, прокси — функции в
`netlify/functions/` (`/odata/*` и `/config`, см. `netlify.toml`). Подключить репозиторий к
сайту в Netlify — и всё. Env-переменные `ODATA_BASE` / `ODATA_USER` / `ODATA_PASSWORD`
необязательны (значения по умолчанию, как `.env` локально).

**Важно:** функция Netlify выполняется в облаке — тестовая база на `10.0.90.102` (внутренняя
сеть) оттуда **недоступна**. Нужен публичный адрес 1С (или туннель), его вводят в окне
«Подключение».

Локально с эмуляцией функций: `npx netlify-cli dev` (или по-прежнему `node server.js`).

## Режим «Напрямую из браузера» (сайт на Netlify + 1С в офисной сети/VPN)

Сервер Netlify не видит `10.0.90.102`, но **браузер сотрудника** (на VPN/офисном Wi-Fi) —
видит. В окне «Подключение» есть режим **«Напрямую из браузера»**: запросы к 1С делает сам
браузер, с Basic-auth заголовком; прокси не участвует. Фреймворк (React/vanilla) роли не играет —
всё решают два условия на стороне **1С/IIS**, без них браузер заблокирует запросы:

### 1. CORS на IIS (обязательно)
Браузер перед каждым запросом шлёт `OPTIONS` **без авторизации**; сейчас IIS отвечает на него
`401`, и заголовков `Access-Control-Allow-*` нет. Нужно установить
[IIS CORS Module](https://www.iis.net/downloads/microsoft/iis-cors-module) и в `web.config`
приложения `unisoft` добавить:

```xml
<configuration>
  <system.webServer>
    <cors enabled="true" failUnlistedOrigins="true">
      <!-- вместо * можно перечислить конкретные origin: https://1cui-txqe.netlify.app -->
      <add origin="*" allowCredentials="false" maxAge="600">
        <allowHeaders allowAllRequestedHeaders="true" />
        <allowMethods>
          <add method="GET" /><add method="POST" /><add method="PATCH" />
          <add method="DELETE" /><add method="OPTIONS" />
        </allowMethods>
      </add>
    </cors>
  </system.webServer>
</configuration>
```
Модуль отвечает на preflight сам, до аутентификации — поэтому `401` на `OPTIONS` исчезает.

### 2. HTTPS с нормальным сертификатом (обязательно)
Сайт на Netlify открыт по HTTPS → браузер разрешит запросы только на `https://10.0.90.102/…`.
HTTPS на сервере уже есть, но текущий сертификат (`CN=1CSerBuh`, самоподписанный) Chrome
**отвергает без возможности исключения** (`ERR_SSL_KEY_USAGE_INCOMPATIBLE`): в Key Usage нет
`Digital Signature`, нет SAN. Нужен новый сертификат — от внутреннего CA, либо самоподписанный
с правильными расширениями (PowerShell на сервере 1С, от администратора):

```powershell
New-SelfSignedCertificate -DnsName "10.0.90.102","1CSerBuh" -CertStoreLocation cert:\LocalMachine\My `
  -KeyUsage DigitalSignature,KeyEncipherment -KeyAlgorithm RSA -KeyLength 2048 `
  -NotAfter (Get-Date).AddYears(5) -FriendlyName "1C OData"
# затем в IIS → Bindings → https → выбрать этот сертификат
```
Самоподписанный сертификат каждому сотруднику придётся один раз принять в браузере
(ссылка «открыть URL 1С» в окне подключения) или установить в доверенные.

После этого: «Подключение» → URL `https://10.0.90.102/unisoft/odata/standard.odata` →
режим «Напрямую из браузера» → «Проверить».
